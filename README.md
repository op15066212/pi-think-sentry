# pi-think-sentry（思维哨兵）

模型在一轮回答里把同一行重复几十遍、或者整段换了语言，这个插件当场判出来并处置。
它不问「觉得对不对」，它数行。

装好之后不用叫它：它在**两个钩子**上等你。命令只有一个，`/think-sentry`。

| 钩子 | 什么时候 | 做什么 |
| --- | --- | --- |
| `tool_call` | 模型要调工具 | **现场判**：取会话历史里最后一条 assistant 的思考，判红就拒绝执行，附一句为什么 |
| `turn_end` | 一轮结束 | 清掉最近 `signature.keepTurns` 轮之外的 thinkingSignature（唯一的写盘动作） |

2026-11-26 使用者把范围收到这两个。原来还有 `before_agent_start`（重置帧级状态）与
`message_update`（每帧判一次）：判决要跨帧传到 tool_call，于是有一堆「上一次判红」的记忆，
而那份记忆会漂移——判据跟着当前思考走，比跟着记忆走可靠。
代价写清楚：不再有「流式过程中就发现退化」的提前量；收益是每帧一次判据的 CPU 没了。

## 两条判据

| 判据 | 判什么 | 门槛从哪来 | 判红后怎么处置 | 反例 |
| --- | --- | --- | --- | --- |
| `dup` | 同一行出现 ≥ `dup.min` 次 | `settings.json` 的 `dup.min`，默认 4 | `strip`：按判据给出的行号删掉重复行 | 一行「做。」连着四遍 |
| `lang` | 非目标语言的行数 > 目标语言的行数 | `lang.dir`，默认 `zh` | `retract`：这一轮不采用 | 整块英文思考，中文只有一行 |

判据只看「投票行」：围栏内的代码、四个空格或制表符缩进的块、空行都不计票。
代码里的重复是正常的，判它会把所有技术对话判红。

先扣后判：自己注入的提示文案在判之前先扣掉。反过来（先判后扣）会让注入文案本身
变成一条重复行——处置自己制造了下一次判红，那是回灌。

## 判决与处置

判决只有四种，写在 `src/verdict.ts`：

| kind | 意思 | 谁产生 |
| --- | --- | --- |
| `none` | 没判红 | 两条判据都可能 |
| `strip` | 删掉指定行 | `dup` |
| `fold` | 把一段折成一行标记 | 历史上是 `inline`（已删，见下） |
| `retract` | 这一轮不采用 | `lang` |

处置不另算一遍：`strip` 用的行号就是判据数出来的那组行号。判一套、改一套，
两边迟早不一样，而不一样的时候看不出来——它只是少删或多删一行。

## 元理论

依赖类型理论是唯一判法。一条规则就是一个类型；说它成立，就要指得出住在这个类型里的居民。
四件缺一不算规则：

| 件 | 是什么 | 缺了会怎样 | 反例 |
| --- | --- | --- | --- |
| 形成 | 这个词落到盘上，对应哪个可查的东西 | 规则悬空，改代码它不跟着变 | 「默认 3」写在文档里，代码是 4 |
| 引入 | 一条命令加它的期望退出码 | 说成立但验不了 | 「按需检查」 |
| 消去 | 换第二个入口算一遍，得同一个答案 | 两处各算一遍，没有比较物 | 同一份输入在两个入口给出两个判决 |
| 反例 | 一个具体输入，喂进去这句话就假 | 只有好样本会绿，判据是恒真 | 「视情况」 |

`src/meta.ts` 的 `RULES` 是这套说法的居民：一共七条（两条产生判决，五条是机制约束）。
每条的四格都要非空，判据是 `npm test` 里 `meta.test.ts` 的那几条用例。

## 配置

一个文件：插件目录下的 `settings.json`，首次启动自动生成，之后不再覆盖。
改完下一次事件前自动重读（按文件 mtime 判断，不靠 `session_start`），不用重启。全部键与默认值见 `SETTINGS.md`。

六个模块：`intercept` / `dup` / `lang` / `signature` / `strip` / `binding`。
默认值只有一处：`src/defaults.ts` 的 `DEFAULTS`。文档与它不一致时以代码为准，判据会告诉你哪边错。

## 判据怎么验

```bash
npm test                      # 单元测试，rc=0
npm run verify                # 上面这些 + 指纹自检 + 总闸，rc=0 才算干净
node scripts/gate.mjs         # 总闸：glob 发现 scripts/check-*.mjs 与根 verify-*.mjs
node scripts/check-rules-coverage.mjs   # 规则表与实现对齐
```

总闸自己也要能红：往 `scripts/` 塞一个 `check-` 开头、返回 1 的临时脚本，总闸必须 rc=1 并点名它。

## 口径上限

这一栏是空的一半，而且看得出来为什么空。

| 抓得到 | 抓不到 |
| --- | --- |
| 同一串字符重复出现（`dup`） | 同一件事换措辞反复推演（语义重复） |
| 语言不匹配（`lang`） | 换个说法再说一遍 |

为语义重复试过八个量（行首集中、残句 3-gram、末句 3-gram、整体 n-gram、跨行词共享、
罕见 token 重复、行首前缀嵌套、跨段首句 3-gram），在 6 个会话 17,667 段上都与正常写作重叠。
不是门槛没调好，是字符级信号与「是否退化」之间没有因果关系。
这段结论写在 `src/meta.ts` 的 `SCOPE_LIMIT` 里，与代码同处一处。

### 删掉的三条判据

删除理由写在 `src/meta.ts` 的 `REMOVED_RULES` 里，不在这里抄第二份：

| 判据 | 删于 | 一句理由 |
| --- | --- | --- |
| `inline` | 2026-11-24 | 句子坍缩在真实数据上没出现过 |
| `run` | 2026-11-24 | 门槛 40 判红 6.2%，抽 14 条全是代码路径重复 |
| `shape` | 2026-11-24 | 量的是写作风格，与「关键：」写作习惯不可分 |

代码不删类型，只不接线：`src/verdict.ts` 的 `Rule` 还留着这三个名字，
因为删了下一个会话会重新发明它们——「行首集中」这个想法很自然。

## 性能

这一项每帧都在跑，所以它有数。11489 字的输入，单次判断（2026-11-25 实测）：

| 实现 | 耗时 |
| --- | --- |
| 改前 | 0.99 ms |
| 改后 | 0.26 ms |

流式一轮 8000 字 / 59 帧：19.15 ms → 5.4–6.4 ms。20000 字 / 59 帧：47.02 ms → 12.5–14.4 ms。
不设阈值：耗时随机器变，卡一个绝对值会把「换台慢机」判成回归。
复现用 `bin/bench-judges.mjs`。

## 装在哪

`~/.pi/agent/extensions/pi-think-sentry/`。改动这个目录之外的任何东西都属于另一个 ownership。

## 排错

| 症状 | 先看 |
| --- | --- |
| 没拦住 | 输出里找 `code.stale`；再看 `binding.capture` 是不是 false（anthropic 系不暴露 thinking） |
| 判红太频繁 | `dup.min` 调高；或看台账 `npm run status` |
| 配置改了没反应 | 配置文件是不是坏 JSON：坏的时候不写、也不覆盖，只在命令输出里说 |
| 签名被清掉 | `signature.keepTurns`（默认 30，按最小轮数：一条 assistant 消息算一轮） |

签字与未验证项见 `SIGN-OFF-DTT.md` 与 `SIGN-OFF.md`。
