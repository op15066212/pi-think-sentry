# pi-think-sentry（思维哨兵）

判三件事。判红之后，**判据给判决、处置改上下文、拦截拒绝一次工具调用**——三个函数，两个出口：

| 判据 | 定义 | 坏样本 |
|---|---|---|
| `dup` 复诵 | 同一行出现次数 **>= dup.min**（默认 4，见 `src/defaults.ts`） | 四行都是 `做。`——min=4 时红 |
| `inline` 坍缩 | 存在一段连续 ≥12 句，其中不同句数 / 总句数 **<= 1/4** | 40 句里只有 3 种——红（`fold`，按行折叠） |
| `lang` 语言 | **非目标语言的行数 > 目标语言的行数** | 一整块英文思考，中文只有一行 |

三条的来源不同，各写清：

- `dup` 与 `lang` 是使用者原话（2026-11-17 与 11-18 两次会话）。
- `inline` 不是原话，是**两次被绕过之后**的产物：模型先把重复压进一行（`dup` 按行计数 → 漏），
  再改成交替与换词（按句找连续 → 漏）。现在判的是结构性质，不认形状。

## 算法层：三条判据 + 一个防回灌

整体处理的意思是**不先切分**。现在的算法层在 `src/algo/` 下，都是纯函数：

| 算法 | 文件 | 回答什么 |
|---|---|---|
| **LZ77 解析** | `algo/lz77.ts` | 这段文本里最长的自我重复有多长（`longest` / `longestNatural`），以及折掉之后是什么样（`deduped`） |
| **Aho-Corasick** | `algo/aho-corasick.ts` | 我注入过的每一段，在这段输出里出现在哪、多长（`scan`），按区间挖掉（`excise`） |

### 判据顺序是三件事，不是细节

```text
一 先扣注入文本    exciseInjected(raw) —— 不先扣，自己注入的文案会被当成退化，直接自锁
二 run 先跑        LZ77 最长匹配 —— 它比 dup/inline 准（不切分），先判的那条决定 ev 形状
三 再 dup / inline / lang
```

**「先扣后判」是硬的**：反过来（先判后扣）会让 `run` 拿未扣除的原文去量，注入文案本身就变成一条长重复。

### 判定与处置同源

`run` 判红时没有行号——它判的是「最长重复多长」，不是「哪一行重复了」。
所以处置走 `dedupByLz`：用**同一次** LZ77 解析的 `deduped` 结果去折叠。
不是「判一套、改一套」，是同一份证据的两种用法。

### inline 判据：按真实数据重写的那一次

旧实现是 `collapseRange`：O(n²) 找「最长的一段**连续**句子，其中不同句占比 ≤ ratio」。

**它在真实数据上几乎不起作用**（50641 段里只命中 129 段，0.3%）。拿 dup 命中当金标准（3384 段），
它漏掉 3143 段——**真实重复是散落的**，连续区间凑不够长度。

三个候选量实测（3384 段金标准 vs 43403 段未标记）：

| 量 | 金标准 p50 | 未标记 p50 | 结论 |
|---|---|---|---|
| `uniqRatio` | 0.750 | 1.000 | **差**，阈值 0.5 只抓到 9%——原判据的核心量不管用 |
| `topShare` | 0.222 | 0.079 | **好**，2.8 倍差距 |
| `repeatCover` | 0.324 | 0.000 | 好，但不是所有退化都有「大半是重复」 |

现在的判据：**`topShare ≥ 0.3` 或 `repeatCover ≥ 0.5`**。
实测金标准命中 33.9%，未标记命中 7.0%（比值 4.8）。复杂度 O(n)。

**回放验证**：inline 从 0.3% → **6.4%**（129 → 3233 段），21 倍；两条以上同时命中 0.6% → 2.5%。

复现：

```bash
node --experimental-strip-types bin/diagnose-inline.mjs ~/.pi/agent/sessions   # 为什么漏
node --experimental-strip-types bin/probe-inline.mjs ~/.pi/agent/sessions      # 三个量哪个能分
```

**inline 整条已删（2026-11-24）**：`collapseRange` / `collapseStats` / features/inline（已删）
一并移除，理由见「口径上限」表里 inline 那一行（11-21 上 0 段）。下面讲形状的段落
保留作历史：它说明过「连续区间」与「整段比例」是两种不同的量。

### 历史回放：真实数据比造样本可信

`bin/replay-history.mjs` 把会话记录里的思考段喂给三条判据，各开各的（不走短路链）。

**跑一次（2026-11-24，4 个文件 / 39876 行 / 15030 个思考段）**：

```text
dup（行复诵）        2056   13.7%
inline（句坍缩）        17    0.1%
run（自然语言重复）     812    5.4%
两条以上同时命中        95    0.6%
```

三件事只有跑数据才知道：

**一、`longest` 在真实数据上错得离谱。** 用它判红 68.8%，例子全是
`C:\Users\15066212pp`、`find -maxdepth`、`*radical*` 这类技术串重复——写代码时正常的引用，不是退化。
加了 `longestNatural`（只算中文占比 ≥ 80% 的匹配）之后降到 5.4%。

**二、`inline` 几乎不起作用。** 15030 段里只命中 17 段（0.1%）。要么删，要么重写，但先要有这个数。

**三、三条判据几乎不重合。** 两条以上同时命中只有 0.6%，说明它们抓的是不同的形状——
这符合「多算法结合」的设计，但也意味着**每条都得单独验**，不能用一条的表现推另一条。

**回放也是探针，探针自己会脏。** 第一版自己拼 `{ t, i }` 对象，把 `kind` 丢掉，
空行全被算进 vote 行，`dup` 命中率冲到 93.2%。改用 `partitionLines` + `voteOf` 之后才是 13.7%。
**误报率是回放唯一有用的数字，探针脏了它就没意义。**

```bash
REPLAY_FILES=8 node --experimental-strip-types bin/replay-history.mjs <会话目录>
```

有界：默认 8 个文件 / 20 万行 / 单段 2 万字。251MB 全读会跑几分钟且吃满内存。

**已知边界**：没做人工标注，所以「5.4% 是误报率」这个说法不准——它只是命中率，真假未标。

## 元理论：依赖类型理论（唯一）

### 证明项精确到这一条

七条规则，每条的「引入」格都是一条**只跑自己那个测试文件**的命令，不是 `npm test`：

```text
dup                  → test/dup.test.ts            16 条
lang                 → test/guard.test.ts          12 条
inject-thinking-only → test/inject.test.ts          5 条
intercept-en-only    → test/deadlock.test.ts        8 条
strip-empty          → test/empty-frame.test.ts     2 条
binding-anthropic    → test/r7.test.ts              6 条
```

**为什么非要这样**：跑全量测试，红了只知道「203 条里有 1 条红」，还得再找是哪一条。
精确到文件，红了就是这条规则红了，直接去看。

验证方法是反过来改坏一处：把 `judges.ts` 里 dup 的 `>=` 改成 `>`，
`test/dup.test.ts` 红 6 条，`test/guard.test.ts` 一条不动。**这才是「只覆盖这一条」的证据。**

判据也写成了代码：`引入` 格必须匹配 `--test test/<文件>.test.ts`，出现 `npm test` 就红。


`Γ ⊢ 规则 : Prop`。一条规则就是一个类型；说它成立 = 指得出住在这个类型里的居民。没有居民就不成立，写 `sorry`，不写「显然」。

四件缺一不算规则：

| 件 | 在这份文档里是什么 | 反例 |
| --- | --- | --- |
| 形成 | 命题里每个词都能落到盘上可查的东西（`dup.min`、`lang.dir`、`settings.json` 六个模块） | 「必要时生效」——盘上查不到它在哪生效 |
| 引入 | 一条命令 + 它该返回的 rc | 只写「已测」，不写退出码 |
| 消去 | 换第二个入口算一遍，得同一个答案 | 两个入口读的是同一处，只算一条 |
| 反例 | 一个具体输入，喂进去这条规则就为假 | 反例格里写「视情况」 |

判法：`node verify-dtt.mjs`（rc=0）；坏样本 `node verify-dtt.mjs --selftest`（五个坏样本全红）；指纹 `node verify-dtt.mjs --fingerprint`（sha256，与 `SIGN-OFF-DTT.md` 里的一致才算签过）。

这套判法自己的反例：文档长得像规则、每格都填着形容词。`verify-dtt.mjs` 判反例格是否为空、判点名的脚本在不在盘上——形容词能过格，脚本不在盘上过不了。
## 「没拦住」先看这一行

```bash
/think-sentry

```

`stale: true` 表示**盘上的代码比进程加载时新**——改完没重启，跑的是旧代码。

## 判决什么时候被清空

判决（`lastV`）只有一个清空点：`before_agent_start`（新一轮开始）。

这条不是设计洁癖，是修出来的：在此之前，每个 `message_update` 都覆盖判决，
而模型写完思考要调工具时，那一帧的 thinking 是空的——空内容判成干净，
**把上一帧的判红洗白了**，于是 `tool_call` 时拦不到。

真实数据（某会话）：判红 790 次、拦下 7 次。差距就是被空帧抹掉的。

现在：空 thinking 帧跳过（trace 记 `empty-keep`），判决保持到下一轮开始。
判据：`test/empty-frame.test.ts` 两条——空帧不洗白、新一轮才清空。

## 防回灌（处置之后不能变成新的来源）

处置会把重复换成一行标记，标记留在上下文里。标记本身可能被模型读到、抄下来。
现在三处都排除了它，否则「处置」会变成下一次判红的来源：

| 出口 | 为什么会被回灌 | 现在 |
|---|---|---|
| 折叠标记 `[40 句…已折叠]` | 抄一遍是 1 种句子，抄两遍是 2 种，越抄越多 | 判据按**形状**排除（`MARK_RE`），抄几遍都不计 |
| 删行标记 `[原第 5-9 行…已删]` | 同上 | 同上 |
| `dup` 判据 | 6 行相同的标记会被数成「复诵 6 次」 | 同样在 `judgeThinking` 入口排除 |

判据：`test/no-reflow.test.ts`——标记抄 6 遍不判红；标记周围有真退化仍然判红（标记不能当挡箭牌）。

## 三个函数，两个出口

判据改了三次，每次都在混淆这三件事——所以单独写清。

| 函数 | 在哪 | 做什么 | 什么时候 |
|---|---|---|---|
| `judgeThinking` | `src/judges.ts` | 判：给一个判决（none / strip / fold / retract） | `message_update`（每帧）、`turn_end` |
| `strip.clean` | `src/features/strip.ts` | 处置：`strip` 删整行、`fold` 折行区间 | `turn_end`（改下一轮会读到的上下文） |
| `intercept.reason` | `src/features/intercept.ts` | 拦：拒一次工具调用，返回原因 | `tool_call` |

**「删除」和「拦截」不是同一个函数**，也不在同一个时机：
删除改的是上下文（下一轮读到什么），拦截拒的是副作用（这一次调用执行不执行）。

`turn_end` 的处置是**循环**：判当前内容 → 红就处置 → 再判，最多 5 轮。
不保存「哪一帧红过」——内容是唯一真相，处置完再判就是验收。
（保存帧记录会漏两种：一轮里两段不相邻、退化后补一句正常话洗白。）

判据：

```bash
npm run verify                              # 一条命令跑完下面两条（这是总闸）
npm test                                    # 全部；条数以运行时为准，不写进文档
node scripts/gate.mjs                       # scripts/check-*.mjs 全部
node --experimental-strip-types --test test/round-clean.test.ts
npm run e2e                                 # 真实退化样本端到端（判据→拦截→折叠）
```

## 口径上限：它抓得到什么、抓不到什么

**抓得到两件事**：

- `dup`：同一串字符重复出现（整行、整句）。
- `lang`：语言不匹配（该用中文的地方写了英文）。

**抓不到一件事**：同一件事换措辞反复推演。

用户 2026-11-24 指着屏幕说过一次：一段思考里「务实：」前缀层层叠加，
同一件事（「用户说别发错人」）从头推了五遍。那是他说的退化。

在 6 个会话 17,696 段真实思考上（@t=2026-11-24T15:17Z），为抓它试过的量，全部与正常写作重叠：

| 量 | 出处 | 结果 |
| --- | --- | --- |
| 单段行首集中度（六维投票） | shape | 独有捕获 314 段，五个量上与「关键：」写作习惯全部重叠 |
| 段内残句 3-gram | 我 | 务实 0.25 vs 关键 0.33，方向反 |
| 段内末句 3-gram | pi 插件2 提的 | 0.26 vs 0.18，差距不够 |
| 段内整体 n-gram | unified | 最高 0.64，门槛 0.70 一个都不判 |
| 跨行词共享 / 罕见 token | 我 | 务实 0.08 / 0.60 vs 关键 0.08 / 0.61，一样 |
| 行首前缀自我嵌套深度 | 我 | 深层嵌套（>=3）与越线段完全不相交 |
| 跨段首句 3-gram | pi 插件2 跑的 | 两个会话都是 0.042，一模一样 |

结论不是「门槛没调好」，是**这个信号与「是否退化」之间没有因果关系**。
「务实：」与「关键：」都长这样，退化也长这样，不退化也长这样。

两个人在同一批数据上独立量，得出同一个结论：这类退化的同一性在**语义**里，
不在字符里。本插件全部判据都是字符级的，所以它抓不到，而且看不到字符级的路。

**这条边界写在这里，不写在回执里。** 下一个会话看到「抓不到」会换思路；
看到「精度低」只会去调门槛。

### 这一节自己翻过四次车，记在这里

1. 第一次写「dup + lang 都准」——没有抽样，纯凭印象。
2. 第二次写「lang 误报极高，77.5%，98% 是中文夹英文路径」——**脚本 bug**。

3. 这个 bug 我在 R3 犯过一次（nobody 恒 0，同样拿 rule 当 kind）。**同一形状两次。**
4. 第四次不在数字上，在**造样本的人身上**（2026-11-24，pi 插件2 建议记在这里）：
   给 probe-run-by-session 加 selftest 时，我写的「正常散文」样本是
   `"今天把磁盘扫了一遍……".repeat(3)` —— **它本身就是重复**，最长匹配 48，越过 @40 门槛。
   selftest 当场红：`FAIL 正常散文不得越过 @40：over=true 期望 false（len=48）`。
   换成三段不同的话才是 len=0。

第 4 条比前三条狠：前三条是「数算错了」或者「量选错了」，都还能靠另一双眼睛看见。
第 4 条是**我写『正常』时脑子里想的是正常文本，手上写的是同一句话三遍**——
样本先要经得起自己的判据，否则你验的不是判据，是你对判据的想象。

所以「我以为准」和「准」之间差一次抽样；「抽样」和「抽样对」之间差一次算术核对；
「样本」和「样本对」之间差一次拿自己的判据先跑一遍样本。

## 这不是一个防御型插件

`inline` 是 2026-11-23 加的，**2026-11-24 已删**（11-21 上 0 段）。
留下这段是因为它记着「为什么要加它」——那段推理没有错，错的是它量对了形状、
量错了对象：真实会话里没有那种形状的退化。

下面是加它时的理由，因为前一条被绕过两次：
同一行内连续重复（v1 漏）→ 改成按句找连续（v2 漏）→ 模型换成交替与「换词不换结构」。
现在的口径是**结构性质**：区间里有多少种不同的句子，不匹配任何具体形状。
三段真实退化（一行内连续、AB 交替、换词不换结构）在同一条判据下都红，位置不固定也能找到。

多层防御的代价是实测的：

1. **判红比使用者的定义多 51%**（4855 块：定义判红 488、那套判红 735）——多出来的全是「中文里引用代码」。
2. **模型改好之后解除不了**（台账 2678 次 thin、2639 次真复诵、真正拦下 0 次）。

## 环节

    message_update   每帧判一次，记下最后一帧的判决
    tool_call        判决是红的就拦（没有次数上限，没有冷却）
    turn_end         按判据给的行号删重复行；按配置在思考末尾追加一段文案

删重复行用的是判据已经算好的行号（ev.dups 里每组第三项），不按内容再找一遍——那是第二份判据。

## 配置

settings.json，六个模块，每个一个开关加它的参数：

```json
{
  "intercept": { "on": true },
  "dup":       { "on": true, "min": 4 },
  "lang":      { "on": true, "dir": "zh" },
  "strip":     { "on": true, "min": 3 },
  "inject":    { "on": true, "texts": { "dup": "", "lang": "", "clean": "" } },
  "binding":   { "allowGateway": false }

```

命令：`/think-sentry` 看全部状态；`/think-sentry dup min 5` 改一个值。写不认识的值会拒绝并说明，不会静默兜底。

### 输出是给人读的，不是给机器读的

`/think-sentry` 打四行，每行不超过 44 字符：

```text
capture on   code 最新
回合 205  红 47  拦 3  处置 3
dup 4   inline 12句/25%
strip 4   lang zh   拦截 开
```

第一行两个词最要紧：`capture` 说明后端允不允许改写，`code` 说明跑的是不是盘上这份代码（`旧代码(重启)` 就是改了没重启）。

**要机读就加参数**：`/think-sentry json`，返回原来的完整 JSON。

### 不进 pi 也能查：`npm run status`

`/think-sentry` 是 pi 内的命令，脚本与别的 agent 调不到。所以另有一个 CLI 入口：

```bash
cd ~/.pi/agent/extensions/pi-think-sentry && npm run status
```

输出与命令同一个格式，多一节台账（磁盘上的历史，只有 CLI 读得到）：

```text
capture on   code 最新
回合 0  红 0  拦 0  处置 0
dup 4   inline 12句/25%
strip 4   lang zh   拦截 开

台账 3021 红 / 293 拦
去重后 190 次
按规则 dup:2985 lang:20 inline:16
最后一次 2026-11-23 17:07
```

**「台账 3021 红 / 去重后 190 次」这一对是重点**：第一个数含着流式的重复帧，
第二个才是真实判红次数。两个数摆在一起，虚高多少一眼看得出。

加 `--json` 出机读：

```bash
node bin/status.mjs --json
```

```json
{
  "config": { "dup": { "on": true, "min": 4 }, "strip": { "on": true, "min": 4 }, "...": "..." },
  "file": "C:\\Users\\...\\settings.json",
  "lines": ["capture on   code 最新", "..."],
  "ledger": { "red": 3114, "block": 403, "dedup": 269, "byRule": { "dup": 3063 }, "last": "..." }
}
```

`config` 单独给结构化的：机读取数字，不必反过来解析人类那几行。
`lines` 一并给出，是同一份渲染结果，不是重算的。

退出码：0 正常，1 台账读不出（判据失败，不是环境缺失）。

### 四个入口，两种形状

| 从哪进 | 人读 | 机读 |
|---|---|---|
| pi 内 | `/think-sentry` | `/think-sentry json` |
| bash | `npm run status` | `node bin/status.mjs --json` |

四条路走的是同一份计算（`statusLines()` 与 `readConfig()`），不是四段代码。

长度不是审美问题：PiDeck 的通知弹窗没有复制按钮、宽度约 400px，超了就被裁掉，裁掉的部分等于没写。测试里有两条断言守着——行数 ≤ 6、每行 ≤ 44 字符。

每个键的解释（默认值、什么时候改、反例）见 [`SETTINGS.md`](./SETTINGS.md)。

### 四个门槛的默认值

| 键 | 默认 | 管什么 |
|---|---|---|
| `dup.min` | 4 | 同一行出现几次判红 |
| `inline.min` | 12 | 一段里至少几句才判坍缩 |
| `inline.ratio` | 0.25 | 不同句占比低于这个就判红 |
| `strip.min` | 4 | 重复几次才动手处置（应当 ≤ `dup.min`） |
| `threshold`（escape-guard） | 3 | 一段里至少几个转义才还原 |

`dup.min` 与 `strip.min` 要同步：处置门槛大于判红门槛，会出现「判红了但什么都没发生」。
这条矛盾**单看一个字段看不出来**，所以 `readConfig()` 里做了一次跨字段检查，
报在输出的 `问题` 那一行（`strip-gt-dup`）。

### 台账里的数字是次数，不是帧数

`message_update` 是流式的：一段一千多字符的思考会来几十帧。
早期实现每帧判红就记一条，台账里同一条记录会出现五次以上（时间戳与开头全同），
于是「回合 237 红 70」读不出真实次数——**观察面坏了，判据再好也看不出效果**。

现在按文本比对去重：内容变了才记（模型真改了思考，那是新的一次判红）。
判据是 `test/install.test.ts` 里那条「同一份思考不重复记账」：同一文本四帧只记一条，文本改了记第二条。

### `dup.min` 为什么是 4

同一行出现 4 次算复诵。取在「标记」（3 次）与「使用者报告」（7 次）之间：整块只有三行 `做。` 的空转会漏判（台账里约 50 次），换来的是 64 块连拦的死锁解开。

判据：`grep -n '"min"' src/defaults.ts` 应为 4；`npm test` → rc=0。

## 签字是什么

**签字 = 一个指纹 + 一个时刻。两者一起才构成签的对象。**

盘在长不使签字失效——它只说明「我签的是 fba6183d，不是后来的 xxx」。
所以判据不是「盘不许动」，是「签的那一刻 --verify 过一次，DIFF 就不是同一份」。

```bash
node bin/fingerprint.mjs --verify <总指纹>    # 期望 SAME @ <时刻>   fp_rc=0
```

这一条是 2026-11-24 双方来回四次才写准的。中间我写错过一版：
「签的是一个时刻的盘，而盘在长」——那个说法暗示「盘动了签字就失效」，
把 (指纹, 时刻) 这个二元对象压成了一元。复核方改准成上面这句。

同一路还留下三个形状，各自都有对策：

| 形状 | 对策 | 落在哪 |
| --- | --- | --- |
| 数比身份快（报了数，没报是哪一刻的数） | 指纹每行都带采样时刻 | `bin/fingerprint.mjs` |
| 身份比数早（md5 取早了，数取晚了） | md5 与数同刻取 | 输出里 `@settings=<md5> <字节>B` |
| rc 取自链的前一段（`A && B` 只看了 A） | 看整条命令的 rc | `npm run verify` |
| 报了身份之后又改了盘 | 取前取后各看一次 git status，两次都是 0 | 取指纹那一次调用里没有写操作 |

四条凑齐，身份这一栏才闭合。报身份时按这四行写，读者一眼能看出缺哪一行：

  指纹 f0d83d8a6f6935227f06f146991d46d4
  时刻 2026-11-24T16:24:52Z
  取前 git status 0 行，取后 0 行
  npm run verify rc=0

前三条是「取的时间点错了」，第四条方向相反：
「取了身份之后又改了盘，却仍按旧身份报」。

## 改这个插件时的一条硬规矩

**任何「我改了」后面必须跟一条命令与它的 rc。rc 不是你以为的那个数，就是还没改。**

这不是规范洁癖。2026-11-21 一晚栽了两次：

- 签字里写「跨块那条的注释也改了」，盘上没改——两个复核方各自核盘，各自抓到。
- 回复里写「PR.md 两处一并改成 dup.min」，提交里根本没碰 PR.md——复核方用 `git show --stat <sha> | grep PR.md` 返回 rc=1 钉住。

两次形状一样：**改完没跑判据就写「改了」**。字面的「改了」和盘上的字节是两件事，只有命令与 rc 能把它们连起来。

改这个仓库时，判据写法：

    grep -n '<被替掉的旧串>' <文件>        # 应无输出，rc=1
    git show --stat <提交> | grep <文件>    # 应命中，rc=0
    npm test && npx tsc -p tsconfig.json --noEmit
