## 3 三个问题

### 3.1 拦截文案要不要彻底「只引用、不劝告」？——**改，但不是因为「会被抄」**

数据说它没被抄过。但「用中文重写这几行，然后重新调用工具」这半句仍然该删，理由是**可删的冗余**，不是可复制：
- 模型已经从「这次工具调用没有执行」知道调用失败，从「N 行不是中文」知道原因。
- 「重写这几行」没有增加可复算的事实，只是重复了一遍结论。
- 删掉后 reason 从 45 字降到约 28 字，且**不含祈使句**。

**判据（可机判、可红）**：`reason` 的每一句要么是常量（「这次工具调用没有执行」），要么含一个来自 `v.ev` 的占位符；且**整段不含祈使动词**（请/应该/不要/重写/保持/注意/务必）。
坏样本：把「用中文重写这几行」加回去 → 测试红。

**但改文案之前，先加一条观测**（R5 那次的做法，我建议沿用）：
- 在 `judgeThinking` 之后、覆盖 `lastV` 之前，若本帧 thinking 含拦截文案的固定前缀（「这次工具调用没有执行」），**计一次 `echoed`**，不拦、不改。
- 判据：`echoed > 0` 才说明「模型真的在抄」，那时再改文案就是被数据驱动的；现在改是被猜测驱动的。
- 这条观测本身有坏样本：手造一个含该句的块 → `echoed` 必须 +1。

### 3.2 `lang.lineChars`（5）该不该让用户改？——**不该**

现在代码里是 `countTarget(line.t, dir) >= 5` 的硬编码（judges.ts:218），注释写着「5 不取 8：实测『PluginConfigUpdateRequest 定义在别处（models）。用 PUT』只有 6 个汉字，8 会误判」。

它是**补偿项**，不是判据：字符比判据（`lineRatio >= cfg.langLineRatio`）会把「说中文但夹一串英文标识符」的行判成非中文，5 是用来修这个误判的地板。

搬出去会发生什么，可算：
- 改成 1 → **行投票恒绿**（每行都有一个汉字），整条行投票判据失效；
- 改成 99 → 只有长行算目标语言，行投票几乎不红。

两个方向都让它变成「恒绿或近似恒绿」，正好撞上提案自己的判法第 3 条。**同理 `LANG_MIN_DIGITS=100` 也不该搬**——提案第五节的坏样本就是「minDigits=99999 → 所有块不因块级判红」，说明你知道它改了会失真；那为什么还让用户能改它。

**该搬的是 `BOUNDARY_MIN_EXEMPT`（现在的 3）**：它是「几行豁免算整段不可见」，两个方向都不是恒绿——改 1 会误判 `    ls -la\n    cd` 为 opaque（保守），改 99 会让未闭合围栏的内容进投票从而判红（也不是恒绿）。这才是「严格度」，不是「语义」。

**所以配置化清单我改成：搬 1 个（boundary.minExempt），不搬 2 个。**

### 3.3 escape-guard 要不要加「每个替换验可逆」的运行时判据？——**不要，那条判据恒真**

要加的那条大概是：

```js
JSON.parse('"' + p.repl + '"') === JSON.parse('"' + p.seg + '"')
```

它在构造上恒成立：`p.text = JSON.parse('"' + p.seg + '"')`，`p.repl = JSON.stringify(p.text).slice(1, -1)`，于是 `JSON.parse('"' + p.repl + '"') === p.text` 是 stringify/parse 互逆的必然结果。**加了它，永远不会有输入能红**。

这正是 escape-guard 自己已经删过两次的形状：`unit-mismatch`（JSON.parse 保证每个 \uXXXX 产出一个码元）、设计阶段的 C5（首次与再现动作相同，条件恒假）。第三次加同一条，是让它再犯一次。

**该加的是能红的坏样本（测试，不是运行时）**：把 `replacement` 改成 `return text`（不转义）→ 含引号或反斜杠的段必须红。这是唯一能抓住「replacement 被改成有损」的判据。

运行时的等价物已经有了：`settle` 的 `saved === expected`（字节恒等式）+ 幂等（还原后再扫 0 点，我在 0.1.5 轮 fuzz 过 867 段 0 残留）。

## 4 模块化：形状可以，但有三样不进 MODULES

escape-guard 改成 `{ name, defaults, configure }` 的形状没问题，理由（加功能不改进三个地方）成立。但边界要写清：

| 不进 MODULES | 为什么 |
| --- | --- |
| `slots.ts`（槽位 → 动作） | 它是**动作映射**，不是功能开关。把它做成可配置，等于让用户把 S1 改成 `none` 而 UI 上看起来「关了一个模块」——同一个事实两个入口 |
| `judges.ts`（判据） | 判据不是功能，是**所有功能共用的尺**。think-sentry 的 `dup` / `lang` 模块只持有 defaults 与 configure，判据在 judges.ts——escape-guard 照抄这个分工 |
| `verdict.ts`（形状校验） | 同上，它是「返回的东西会不会改坏消息结构」的地板 |

能进的是提案列的六个：toolResult / assistant / provider / report / seen / scanPolicy。其中 `scanPolicy`（threshold / strict / ratio / bodyCjk）是唯一有争议的一个——它与 `judges.decisive` 的默认值必须同源，否则又是「一个值两个像」（0.1.2 那轮的真缺陷）。搬的时候让 `judgeCfg()` 从模块 defaults 读，而不是在 judges.ts 里再写一份默认值。
