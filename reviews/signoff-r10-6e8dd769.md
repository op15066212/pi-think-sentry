## 2 但我构造出的反例（可复跑，这是不认可的唯一理由）


这正是用户报的那个病：**模型已经改好了，插件不认。** 而且是同一个机制里的一处：

```
src/index.ts:298  const needChars = Math.max(String(lastRedV?.ev?.blk || "").length * (jcfg.dupMin || 3), (jcfg.dupMin || 3) * 8);
```

第一项用 `blk.length × dupMin` 当门槛。而 `blk` 是**模型上一帧复诵的那一行**——它越长，解除时要写的字越多。用户那个会话里模型复诵的是一段英文，复诵得越长，欠债越大，而**这笔债的长度是模型自己控制不了的**（它当时正被判红，越慌越复诵长句）。

换一个说法：你把「恒不满足」改成了「与错误长度成正比」。17 段真实数据里没有长 blk，所以 cooled=0 是真的；换一段长的，就是又一个死锁。

**修法建议**：不要用 `blk.length` 做乘法分母。用两个可说的量之一：

- 固定下限（`dupMin × 8 = 24`）就够了——它挡的是「两行同上」，不需要按错误大小加码；
- 或者用**本帧可投票字符数**与上一帧被判红时的可投票字符数比（`本帧 >= 上次的一半`），那个量两帧都是模型真正写下的内容。

判据（加进 `test/deadlock.test.ts`，现在会红）：上面两帧，帧2 必须 `block=false`。

### Q2 删掉「正文行无复诵」有没有放过什么：**有，但放过它的不是这条**

这条本身删得对：正文复诵由 `judgeThinking` 判（`dupMin=3`），`releaseEvidence` 再查一遍是重复判据，而且会误伤「真实思考里列表项成对出现」。

```

```

### Q3 「至少 3 行」删得对不对：**不对，理由不成立**

你的理由是「现在由 `dupIn(vs, 2)` 与字符量挡」。两处都不成立：

1. `dupIn` 现在只作用在**豁免区**（`releaseEvidence` 第 426 行 `dupIn(exempt, cfg.dupMin)`），正文行它根本不看；

也就是说：删掉行数条件之后，挡「凑数」的只剩「24 个不同字符」。这个数量级是两行废话就能凑到的。
