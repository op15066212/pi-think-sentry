## 一、提案漏的一处违规（硬证据）

```
$ grep -n "已删除" src/features/strip.ts
47:      if (!next.trim()) return [{ ...c, thinking: "（这一段的重复行已删除）" }];
```

它写进 `thinking`：**下一轮模型读到的是这句**，不是一句给用户看的话。而 SAY_LANG 至少写在 toolResult 里、带上下文（「你上一次的思考里」）。
按你第一节的判据（插件写进上下文的每个字符串，必须是从原文截取/解码，或是带占位符的模板），这句两条都不满足：
它不含任何占位符，也不是原文——它替代的恰恰是被删掉的那几行，而那些行**已经不在了**，所以连「引用」都做不到。

修法只有一条：**删空时不写话**，或者写「这一块原有 {{n}} 行，全部重复，已清空」——后者至少带一个数字。
但「n」也是自造的语义。更彻底的是**不给空块**：见第三节的 Q1 替代，把「空」交给一个不写 thinking 的方式处理。

## 二、你让我验的判断：escape-guard 天生安全？

**结论对，理由要换，且你的判据有漏洞。**

先说对的：我把 escape-guard 写进上下文的所有字符串过了一遍——`toolResult.ts` 只替换 text 块的内容、`assistant.ts` 同理、
`provider.ts` 不改 payload、`seen.ts` 写的是 state.json（不进上下文）、`stats/summary` 只给人看。
所以「不新增句子」成立 ✓。

漏洞在这一句：你的判据 1 是「是从原文截取或解码得到的（引用式）」。**任何改写都能声称「来自原文」**——
`strip.ts` 那句占位话也可以说「我来自被删的行」。所以判据 1 不是可执行的判据，是措辞。

要写成可执行的，得把它换成**逐字符可解释的映射**：写进上下文的文本与原文本之间，每一处差异都能指到一段原文区间。
按这个判法：

| 输出 | 差异是否逐段可解释 | 判 |
| --- | --- | --- |
| escape-guard 的解码替换 | 每一处 `\uXXXX` → 一个字符，位置一一对应 | ✓ 安全 |
| SAY_LANG / SAY_BLOCK | 整段是新的，原文只是被拼进去的片段 | ✗ |
| strip 的占位句 | 整段是新的，原文区间被删了 | ✗ |

**所以「天生安全」应改成「在自我模仿这个维度上安全，在内容正确性维度上另由两条判据管」**——
它唯一能写错的地方是解码错（把代码里的 `\u4f60` 解成汉字），那由 C1/C3 与恒等式管，不由这条管。

## 三、三个问题

### Q1 拦截文案改成「只引用、不劝告」？

**要改，但方向反了：不要引用原文，要用指针。**

理由是可测的：引用原文 = **把英文再复制一遍进上下文**。提案的修法是「引用模型自己写的那几行」，
而那几行正是要消掉的污染——引一次等于给它加一次曝光。这与「让下一轮没有可抄的样本」直接冲突。

指针式（只给位置与量，不给内容）：

```
lang : 工具调用未执行。第 {{start}}–{{end}} 行不是{{lang}}，共 {{lines}} 行 / {{chars}} 字符。
block: 工具调用未执行。第 {{lineNo}} 行重复 {{reps}} 次。
```

两处都只有事实，没有祈使句，没有可内化的句子——**动作由「工具调用未执行」这个事实暗示**（它必须重试）。
模型要定位那几行，读自己的 thinking 即可（行号在它的上下文里有效）。

判据（可执行，能红）：

```
模板去掉占位符后，最长连续固定片段 <= 30 字符；且固定片段不含任何一轮 thinking 里出现过的行。
坏样本：把 SAY_LANG 改回「用中文重写这几行」→ 固定片段 43 字符 → 红。
```

「不含任何一轮 thinking 里出现过的行」这条可以直接用会话记录跑：拿 22 次拦截后的下一轮 thinking，看里面有没有复诵文案的行。
你说「用户截图里模型写过 Keep thinking pure Chinese」——**那条截图证明的是「劝告会被内化成英文版本」，不是「文案被逐字抄」**。
这个区别很重要：前者只要去掉劝告就消失，后者要改模板。我的修法同时压住两者，但判据要按前者写，否则永远找不到坏样本。

### Q2 `lang.lineChars`（5）该不该让用户改

**不该。不是因为它「拟合出来的」，是因为它非单调。**

```
lineChars = 1     → 每行一个汉字就过线 → 判据回到 R5 之前的恒绿状态（实测红块 2/533）
lineChars = 5     → 现在这样（R5 后红块 44）
lineChars = 99999 → 行投票永不通过 → 只剩块级判据在判 → 与「删掉行投票」等价
```

两端都是判据失效，只有中间一段有效。**配置系统能夹住单调参数的边界（且 minDigits >= 0、ratio ∈ [0,1]），夹不住「两边都坏」的窗口。**
所以按你自己的三条判法，它违反第 3 条（改了不会让判据变成恒绿）——它在两边都会让判据恒绿/恒红。

同一判法下可搬的：`LANG_MIN_DIGITS`（单调，越小越严）、`boundary.minExempt`（单调，越小越严，>=1）。
它们搬了只会让判据变严或变松，不会让它失效。

替代：把 5 固定成常量，但**加一条测试锁住退化**：`lineChars=1` 的行为（红块 2）写成测试名 `lineChars=1 会退化成恒绿`，
这样将来有人想把它改成配置项时，会先撞到这行测试。

### Q3 escape-guard 要不要加运行时判据

**你写的那条（每个替换验 `replacement(text)` 可逆）是恒真判据，别加。**

```
$ node --experimental-strip-types %TEMP%/r6-idem.mjs
B replacement 可逆（5 个边界样本，不可逆数）   0
```

`JSON.stringify(s).slice(1,-1)` 与 `JSON.parse` 互为逆函数，这是 JSON 规范保证的，不是我判出来的——
与 `unit-mismatch`（JSON.parse 保证每个 \uXXXX 一个码元）、`points/attempted`（两行同源）同族：**改了没有输入能让它红**。

该加的是另一条，它可红：

```
替换后重扫 = 0 点：scan(applyPoints(text, points)).points.length === 0
```

理由：替换是「把转义段换成字符」，若 replacement 生成了新的 `\u` 序列，下一轮 S1 会再替换一次——
那是**不稳定**，而不是错。我 fuzz 过：

```
A 幂等性：1167 个替换样本，替换后再扫仍有点的 0
```

0 例外，说明现在的实现是稳定的。**「0 例外」正是好样本该有的样子**；坏样本是「把 replacement 改成返回原段文本」→ out == text → 重扫仍有点 → 红。
这条判据现在就能写，且它在测试与运行时都能跑（`settle` 里已经算了字节恒等式，再算一次点数几乎零成本）。

## 四、配置化清单：逐条判

| 提案条目 | 我的判 | 依据 |
| --- | --- | --- |
| `lang.minDigits` (100) | ✓ 搬，`>= 1` | 单调：越小越严，夹住下界即可 |

你这三条筛子（有意义 / 值域可穷举或可夹住 / 不会让判据恒绿）里，第三条其实是第一条的推论——非单调就是「会让判据恒绿或恒红」。

## 五、模块化：可以搬，但别把策略伪装成功能

你列的六个模块里，只有三个是真功能（`toolResult` / `assistant` / `provider`，各带 `on`）。
`scanOp` / `seen` / `report` 没有 `on` 开关——把它们的参数塞进 `defaults` 是合理的，但别给它们 `name` 相等的地位，
否则「关掉一个功能」这个概念就会被稀释成「改了一个参数」。

写法：`MODULES` 里带 `kind: "slot" | "policy"`。`slot` 必须有 `on: true`，`policy` 的 defaults 只有参数。
判据：遍历 MODULES，`kind === "slot"` 的必须有 `on` 键，否则测试红——这条能挡住将来「加了个模块但忘了开关」。

至于「加一个开关不该改三个地方」这个理由，我认：现在 `Cfg` 类型 + `DEFAULTS` + `guardText` 里的判断确实三处。
但改完之后请留一条判据证明它：**删掉 DEFAULTS 里某个键，只有一处报错**（类型检查），而不是三处静默。
