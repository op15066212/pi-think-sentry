# R5 提案：把拦截改成改写（thinking 层）

## 一 观察（现取，数学组1 = 会话 01a1f667）

样本：6.3 MB，1274 条目，622 条 assistant，519 个 thinking 块，47.8 万字符。

| 量 | 值 |
| --- | --- |
| 整体中文字符占比 | **0.273** |
| 纯英文块（CJK=0） | 11 |
| 中文过半的块 | 6 |
| 0.1–0.6 之间的块 | **490**（94%） |
| 工具调用 / 失败 | 603 / 23 |
| 本插件拦截次数 | 22（「上一次的思考里」） |

**拦截的效果**（20 对「拦→下一次 thinking」配对）：

| 结果 | 次数 |
| --- | --- |
| 改善（CJK 比 +0.05 以上） | 14 |
| 持平 | 4 |
| 恶化 | 2 |
| 平均变化 | **+0.19**（0.27 → 0.46） |

## 二 诊断

拦截**有效，但不够**：七成情况会改善，平均只到 0.46，离「全中文」差一半；而且会反弹（两次恶化）。

原因不在判据（它报得准），在**作用点**：

> 拦截改的是 **action**（工具调用被打回），而污染的是 **context**（它自己写出来的 thinking）。
> 打回工具，模型只能再想一遍；而它读到的上一轮 thinking 还是英文，于是照着写。

模型自己说过「Keep thinking pure Chinese」（用户截图 18066212pp 18:23）——它知道，做不到。**知道与做到之间隔着的是上下文里那段英文样本。**


## 二·五 另一条关键数据：连续判红从未发生

21 次拦截，21 次都是孤立的单次，链长 >=2 的次数为 0。

两件事同时成立：整体 CJK 比 0.273（很差），但从不连续判红（表现很好）。

解释只有一个：**模型学会了刚好过线**。判据是行级的（有几行不是中文），它就只把那几行改成中文，
其余 73% 的英文一字不动；判据一过，拦截就停，污染继续。

这条数据把方案重心挪了：不是拦得更狠，是**判据太松 + 作用点错**。
它同时否掉了原计划的 L2 阈值——连续 2 次替换在现有数据里永不触发，
那会是一条没有样本的判据，与上一轮删掉的 unit-mismatch 同病。
## 三 方案：三个作用力，按可逆性分三级

对象只有一个：**落盘前的 thinking 块**。动作也只有一个方向：让下一轮没有可抄的样本。

| 级 | 动作 | 可逆性 | 什么时候用 |
| --- | --- | --- | --- |
| L0 | 拦截 + 换提示（现状） | 完全可逆 | 第 1 次判红 |
| L1 | **追加**一条轮换提示到 thinking 末尾 | 保留原文，只是加尾巴 | 第 1–2 次判红 |
| L2 | **替换**整块为一条轮换提示 | 丢失推理内容 | 连续 ≥2 次判红 |

**永不删空**：空 thinking 块会被部分 provider 拒收，且模型失去工作记忆，容易开始重复同一句。

## 四 轮换为什么是必需的

固定文案会被模仿：模型读到「用中文重写这几行」五次，第六次开始把这句话也当自己的思考内容写出来——那时判据仍然红，但提示失效，变成背景噪音。

轮换规则（要三方定）：
- 池子 4–6 条，每条长度与句式不同（避免结构也被模仿）
- 取用按 **turn 序号 % 池长**，不用随机（随机会让「同一轮重放」不可复现）
- 每条都带一句「这是外部提示，不是你要续写的内容」——防止它把提示当思路接着写

## 五 判据（怎么证明它有效，怎么证明它坏了）

| 断言 | 判据 | 现在 |
| --- | --- | --- |
| 改写生效 | 落盘后该块以提示结尾 | 无 |
| 轮换生效 | 连续 3 轮判红，三条提示互不相同 | 无 |
| 不删空 | 任何块 thinking.length > 0 | 无 |
| 效果 | 拦截后 CJK 比均值提升 | +0.19（基线） |
| 不倒退 | 不出现「越改写越红」的长链（连续红 ≥5） | 需记录 |

**坏样本**（改回去会红）：把 L2 的阈值从 2 改成 99 → 「连续三次判红会被替换」这条测试必须红。

## 六 风险（要三方逐条判）

1. **thinkingSignature 校验**：Anthropic 系是 opaque 的，改内容可能被拒。本机当前模型签名是常量 `reasoning_content`，安全；方案必须写成「signature 非常量时不改写」。
2. **丢工作记忆**：L2 替换掉一段推理，模型可能忘记任务进度。缓解：提示里带「你正在做的事见上一条工具结果」。
3. **变成新样本**：轮换池被读多了也会被模仿。缓解：池子里混入一条「不要模仿以上任何句子」。
4. **缓存失效**：改 thinking 会让前缀变化，缓存命中下降。这层改动发生在 turn_end（已落盘之后），下一轮请求前缀确实变了——代价要量出来。

## 七 要三方回答的三个问题

1. L2 的触发条件：连续判红不可用（21 次全是孤立单次，永不触发）。改成什么？候选：本会话累计判红 >=3 / 本块 CJK 比 < 0.15 / 本轮 thinking 超过 2000 字符且 CJK < 0.2。
2. 替换的是「判红那一块」还是「本轮所有 thinking 块」？
3. 拦截本身要不要保留？（若 L2 已经改写上下文，打回工具调用还有意义吗）
