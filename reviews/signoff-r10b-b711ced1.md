## 三、你请我判的边界：判断对，但数字要说得更准

你说「恰好凑够 24 个不同字符的垃圾能过」。实测门槛确实在 24，但成本比那句话低一半：

```
两行各 12 个不同字（共 24）         → 放行
两行各 10 个不同字（共 20）         → 拦
同一行 12 个不同字，写两遍          → 放行   ← 12 个字就够
同一行 20 个不同字，写两遍          → 放行
同一行 12 个不同字，写三遍          → 拦（dup 判红，两遍是上限）
```

原因是字符量按行累加、**跨行不去重**：同一行写两遍，那 12 个字算两次。所以边界的准确说法是
「一行 12 个不同字写两遍」，不是「24 个互不相同的字符」。

**这个边界我判对**：它与整段口径一致（3 次才算复诵，2 次在真实清单里是常态），
要堵它只能把形状判断请回来，而那正是这一轮删掉的东西。留下它并写清，是正确取舍。
只请你把上面那个更准的数字写进注释——否则下一个人会以为要 24 个不同字。

## 四、要改的那一条：最强判据在文件缺失时静默 pass

```
test/deadlock.test.ts:103
if (!fs.existsSync(SRC)) return;   // 归档之后这条跳 SKIP，不冒充通过
```

在 `node:test` 里，测试函数 `return` 就是**通过**，不是 skip。实测（把路径改成不存在的文件名）：

```
ℹ tests 6 / pass 6 / fail 0 / skipped 0 / cancelled 0     ← 一致性那条报 pass
```

所以那句注释说的「不冒充通过」没有实现：它正是冒充通过——而且是**最常见的那一种**
（会话归档是常规操作，不是异常）。这条判据是你自称「最强的一条」，它现在有一个一键失效的开关，
而按下去之后 251 条全绿、没有任何提示。

**判据（改哪一行、跑哪条、期望什么）**：

```
# 修法一（推荐）：用 node:test 的 skip 标记
#   test("一致性…", async (t) => { ... if (!fs.existsSync(SRC)) return t.skip("会话文件不在：" + SRC); ... })
sed -i "s|2026-11-18T14-10-43-047Z_01a1eefe-dee4-75ad-9ae6-7caebe9c7173.jsonl|__not_here__.jsonl|" test/deadlock.test.ts
node --experimental-strip-types --test test/deadlock.test.ts
#   期望：pass 5 / skipped 1        （现在是 pass 6 / skipped 0）
git checkout -- test/deadlock.test.ts
```

修法二（更保守）：文件不在就 `assert.fail("样本文件不在，这条判据没有执行")`——
但那样归档之后测试会红，需要人改路径，比 skip 麻烦。我推荐修法一：skipped 是可见的状态，pass 不是。
