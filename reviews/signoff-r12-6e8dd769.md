## 0 结论

**不认可。** 删层的方向对，但删完之后 **dup 判据没有出口**，而它在真实数据里命中的主体是「做。」这类动作标记。结果是使用者 2026-11-18 报的那个病（模型改了三次、拦三次）在 0.2.0 里**完全复现**，而且这次连冷却都没有。

## 1 复现（不认可的唯一理由，可复跑）

三段内容**完全不同**的思考，只有动作标记「做。」重复三次：

```
块1 = 做。/ 先看盘上的状态… / 做。/ 读一下判据文件… / 做。/ 跑一遍测试…
块2 = 做。/ 改成从第二处入口读… / 做。/ 补一条测试… / 做。/ 跑全量。
块3 = 做。/ 这次只动一处… / 做。/ 然后改那一行。 / 做。/ 最后跑测试确认。

判据：三块全部 strip/dup，blk 是「做。」，reps=3
真 install：tool_call 第 1/2/3 次 → block = true, true, true
```

模型确实改了内容（三块正文没有一句相同），插件确实每次都拦。这就是 3391–3395 那三条记录的同一个形状。

## 2 数据：dup 命中的主体是动作标记，不是复诵

用 0.2.0 的 judgeThinking 重放盘上全部会话（87 个文件）：

```
thinking 块 37950，判红 3564（9.4%），dup 2762，lang 802
dup 判红里，被复诵那一行长度 <= 5 字符的：2106 / 2762 = 76.2%
最常见的被复诵行：
   913 次  做。
   465 次  跑。
   289 次  接着执行。
   226 次  **跑**。
   215 次  （执行）done。
   178 次  执行。
    85 次  写。
```

抽查 10 个判红块（你问的第 2 件）：2 个 lang 是**纯英文思考**（判红对，那是真的在用英文想）；8 个 dup 的 blk 全是「新的：」「写代码。」「跑。」「写。」「矛盾！」这类——正文是成段中文，只有那个标记重复。

所以 9.4% 既不是「抓到复诵」也不是「误伤」，是**判据在数一个模型故意用的写作习惯**。

## 3 按你这轮的规则判 dup：它挡的事故是它自己造成的

使用者的新规则：「每加一层防某人绕过的机制，先说得出它挡的是哪次已发生的事故；说不出就删。」

dup 挡的是已发生的 3391–3395（「同一行 7 次：做。」）。但那三条记录里，模型是在**被拦之后**写「做。」——它在说「我要做这个」。

```
dup 判红「做。」→ 拦 → 模型再写「做。」→ 再判红 → …
```

**它挡的那个事故，是它自己制造的。** 删掉它，那三条记录里的拦截随之消失，使用者报的病也就没了；留下的 lang 判据仍然管着「中文思维链」这个使用者的原话。

这是核心判据：删掉 dup 之后结论会变，所以它不是「加戏」，它是**事故的成因**。

如果一定要留（比如担心模型抄整段注入文案），必须同时留一个出口；0.2.0 把出口全删了，于是它从「误伤」变成「永久拦」。

### Q2 回放数据支持结论吗：不支持

见 §2。9.4% 看起来「抓到了一些」，拆开是 lang 802（对）+ dup 2762（其中 76.2% 是动作标记）。**用总数支持「判据有效」是 census**——数得细不产生解释；拆到「被复诵的那一行是什么」才产生解释，而拆开之后结论反过来了。

### Q3 escape-guard 那 2 个失败样本：不修

修法只有一条：把现在的**整批**字节校验改成**逐段**校验，才能让一部分样本还原。

代价：逐段校验会把「段与段之间的偏移」重新变成可错的地方。而 `src/scan.ts:33` 写着 v1 犯过的三次错——文件层与内容层混算、delta 按解码文本算、按行处理后沿用行内偏移——**全是偏移错**，后果是代码被改坏（中文引号那段直接坏掉）。

所以这是拿「一个已发生过的、会把代码改坏」的错法，去换「污染没还原」（可逆，用户看到的是 `\u` 原文）。按 lean-kernel 的取舍顺序（不可逆保护优先），不修。
