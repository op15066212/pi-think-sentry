### 问三：ref 类是否必要？——必要，代价是真的，而且这一轮已经付过一次

塞进 `fence` 或 `indent` 都不行，理由你已经写进代码注释了：**这两个类都计入 exempt，而 exempt 是 opaque 的分子。**
引用行不是「判据看不见这段」，是「这段没有语言内容」。混进去之后，贴一堆路径就能把已判红的拦截洗成 opaque。
这是同一个洞，不是新洞。

塞进 `blank` 也不行为两件事：blank 的语义是「空行」，引用行是文本；更实际的是 dup 要覆盖它——
「同一行路径贴三次」是自我模仿，塞进 blank 就得让 `dupLines` 再特判一次 blank，那比第五类更绕。

**代价要写明**：五类意味着每一个「按 kind 过滤」的点都要重新想一遍，漏一处不报错、只静默。
这一轮你已经付过一次学费——dup 的覆盖面从 vote 扩到 vote+ref，注释里写的就是这个。
现在的护栏是 `LineKind` 是联合类型 + `boundaryJudge` 的计数表五个键都初始化了（漏键会变 NaN，不会静默）。
这个护栏够用，但它只挡「新增一类时忘了加键」，挡不住「新增一类时忘了扩某个 filter」。

### 2. 「同一段思考只拦一次」与实测不符：A / B / A 会被拦两次

`src/index.ts:320` 的键是 `lastBlockedText`——**单槽**，只与上一次比。复跑：

```
A1 → 拦
B1 → 拦
A2（同一段思考 A 又回来）→ 拦        ← 注释说「同一段思考只拦一次」
```

注释（`index.ts:306-307`）写的是「同一段思考只拦一次；模型改了思考才再拦」。
A2 时模型确实改过思考（中间插了 B），按字面应当放行，实测拦。
两种改法，选一个：把注释写成**「连续同一段只拦一次」**（承认单槽，代价最小），
或把键换成有界的最近 N 段集合（N 取 2–3，仍然可停）。我倾向前者——单槽的边界是真的，但写成集合就把「可停」的证明成本抬高了。

### 3. 「配了但不合法要记账」对门槛类不成立：同时两条配错，前一条静默消失

`values.ts` 的 `rejects` 是**数组**（能全记），`threshold.ts` 的 `lastRejected` 是**单槽**（只留最后一条）。
同一个概念——「配置值不合法」——两个台账，其中一个会丢。复跑：

```
# 配置文件写 {"dup":{"min":-2},"strip":{"min":"x"}}，然后 think-sentry 显示状态
lastRejected = "\"x\""        ← 只有 strip 那条
#  config.dup.min = 3           ← dup 的 -2 静默退回默认，没有任何地方说它被拒了
```

对照：同一次读取里 `{lang:{ratio:"abc"}}` 与 `{intercept:{boundaryMinExempt:0}}` 都进了 `rejects`（数组），看得见。
所以这不是「门槛类不记账」的设计选择，是**两条路径的记账能力不一样**，而这一轮的判据原文是
「配了但不合法退回默认并记账（`rejectsOf()`，命令输出里能看到）」——门槛类不在那句话的范围内。
改法：`threshold.ts` 的 `lastRejected` 换成数组，或在 `readConfig` 里统一收进 `rejects`。
判据：`{dup:{min:-2}, strip:{min:"x"}}` 之后 `rejects.length === 2`，删掉任意一条会红。
